# Чек-лист разработчика после комментариев в PR

## 1. Прочитать все комментарии
- [ ] Я прочитал все замечания в PR
- [ ] Я отделил blocking comments от рекомендаций
- [ ] Я понял, какие комментарии обязательны к исправлению

## 2. Понять проблему
- [ ] Я понял, что именно в коде не так
- [ ] Я указал, к какому файлу и участку кода относится замечание
- [ ] Я проверил, не влияет ли проблема на поведение системы в продакшене

## 3. Внести исправление
- [ ] Я внес правки только в контекст замечания
- [ ] Я не смешал исправления из разных тем в один коммит
- [ ] Я сохранил архитектурную логику и не сломал текущие сценарии
- [ ] Я проверил, что исправление закрывает именно этот комментарий

## 4. Проверить повторно
- [ ] Я прогнал локальную валидацию
- [ ] Я проверил bash-syntax / shellcheck / unit / smoke / integration, если есть
- [ ] Я подтвердил, что исправление не создало новых регрессий

## 5. Обновить PR
- [ ] Я сделал новый commit в ту же ветку PR
- [ ] Я обновил PR после исправлений
- [ ] Я убедился, что CI/Workflow снова запустился

## 6. Проверить закрытие замечаний
- [ ] Я ответил на комментарии с указанием, что было исправлено
- [ ] Я подтвердил, что критерий закрытия замечания достигнут
- [ ] Я не оставляю “пустые” ответы без изменений в коде

## 7. Принять решение о готовности PR
- [ ] Все blocking замечания закрыты
- [ ] Все обязательные workflow checks зелёные
- [ ] Нет забытых комментариев с критическим статусом
- [ ] PR готов к повторной проверке / merge

## 8. Что запрещено
- [ ] Нельзя создавать новый PR вместо исправления текущего
- [ ] Нельзя игнорировать blocking comments
- [ ] Нельзя мержить PR без повторной валидации после правок
- [ ] Нельзя закрывать замечание без фактического изменения кода

## 9. Шаблон ответа на комментарий

> Исправлено в <файле/коммите>. Обновлён сценарий <описание>. Повторно проверил: <какие проверки>.
>
> Критерий закрытия замечания: <что подтверждает исправление>.

## 10. Если замечание не закрывается
- [ ] Я уточнил, что именно не устраивает reviewer
- [ ] Я запросил дополнительную информацию, если нужно
- [ ] Я не ставлю “fixed” без фактической проверки

---

## 11. Минимальный required checklist перед merge

- [ ] PR зелёный
- [ ] Все blocking замечания закрыты
- [ ] Все нужные тесты прогонены
- [ ] Нет незаполненных комментариев по коду
- [ ] Коммит после правок отправлен
- [ ] Workflow снова запущен
